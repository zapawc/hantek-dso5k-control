# TEL-SVC-01 local instrument service

The service owns the retained DSO5102P rear interface on one Windows worker. It uses the existing cooperative mutex, WinUSB validation, interruption marker and guarded finalization. The HTTP threads only read memory or queue an operation. They never open the scope. An unresolved command or unverifiable restore stops USB work, releases resources where possible and keeps the interruption record for review. Firmware 3.40.0 (151009.0) and the authorized Workbench fixture are the supported profile. [ADR-005](../adr/0005-proportionate-instrument-qualification.md) · [ADR-006](../adr/0006-workbench-acquisition-development.md)

## Start and use

Use the reviewed clean source checkout on Windows and the existing WinUSB assignment. Use a fresh private evidence directory on the same volume as the interruption-state directory. The evidence directory contains waveform data and an API credential. Keep it private.

```powershell
python -m pip install -e '.[winusb]'
$env:PYTHONPATH = Join-Path (Get-Location) 'src'
$revision = git rev-parse HEAD   # Verify this against the reviewed commit.
python -B -m hantek_dso5k.service --live --source-commit $revision --evidence 'C:\private\new-service-run'
```

Use a second console from the same checkout.

```powershell
$client = 'C:\private\new-service-run\client.json'
python -B -m hantek_dso5k.service_client $client status
python -B -m hantek_dso5k.service_client $client settings
python -B -m hantek_dso5k.service_client $client measurements
python -B -m hantek_dso5k.service_client $client snapshot
python -B -m hantek_dso5k.service_client $client triggered --path auto --allow-overwrite
python -B -m hantek_dso5k.service_client $client job --job-id <id>
python -B -m hantek_dso5k.service_client $client artifact --job-id <id> --artifact waveform.json --output .\new-waveform.json
python -B -m hantek_dso5k.service_client $client shutdown
```

Startup and polling preserve the current acquisition mode, probe settings and measurement slots. The explicit client `run --allow-overwrite` and `stop` commands change only the acquisition state with readback. Starting Run or arming SINGLE can replace a stopped record. A native snapshot does not change settings or Run/Stop. The retained sender can modify volatile display samples while serving native output. Frozen capture creates new front-media files and keeps them.

Polling takes one configured S22 item per turn, in two-channel rotation. Every pass starts with S81. `--poll-interval` adds time between completed items, with a default of 0.25 s. `--stale-after` sets the host observation threshold in seconds, default 45. `--measurements` selects a comma-separated subset of mean, minimum, maximum, vpp, frequency and period. A long interval with many items also requires a longer stale threshold. The socket is bound only to `127.0.0.1`. The default port is ephemeral. Set `--port` for a fixed local port.

## API contract

Every request uses `Authorization: Bearer <token>` from `client.json`. POST bodies are JSON, up to 4 KiB. The example client bypasses proxies and redirects and accepts only the IPv4 loopback endpoint. No UI, remote endpoint or cloud relay is included.

| Method and resource | Action |
| --- | --- |
| `GET /v1/status` | STARTING, MONITORING, CAPTURING, STOPPING, STOPPED or FAULT, connection, scheduler counters, job IDs and error. |
| `GET /v1/settings` | Latest S81 snapshot, observed UTC, raw and configuration SHA-256 and decoded acquisition/probe/slot state. |
| `GET /v1/measurements` | Latest cache entries. No instrument request is generated by reading the cache. |
| `GET /v1/capabilities` | Selected poll items, supported operations, capture paths and coherence state. |
| `POST /v1/jobs` | Queue one operation. Returns HTTP 202 and an ID. A concurrent capture or already queued operation returns 409. |
| `GET /v1/jobs/<id>` | QUEUED, RUNNING, SUCCEEDED, FAILED or CANCELLED, with result, artifact descriptors and error when available. |
| `GET /v1/jobs/<id>/artifacts/<name>` | Serve a named result JSON or CSV with recorded byte count and digest verification. |
| `POST /v1/shutdown` with `{}` | Stop admission, cancel a queued job and let the in-flight operation finish before releasing ownership. |

Example job bodies.

```json
{"kind":"snapshot"}
```

```json
{"kind":"triggered","path":"auto","allow_overwrite":true}
```

```json
{"kind":"run-state","running":true,"allow_overwrite":true}
```

`s22-probe` is an explicit diagnostic job for source 0/1 and modes 0/1 with Frequency and Vpp. Its default reads the current state. Request `{"kind":"s22-probe","configure_fixture":true}` or use the client flag `--configure-fixture` to compare against the verified scale/probe settings on an already running fixture and then restore. Measurement slots stay unchanged. The service keeps up to 64 job records in memory and retains files under their private per-job directories. The API does not accept raw wire requests or arbitrary file paths.

Every measurement includes the channel and item, SI value/unit, display text, source, UTC observation, host age, availability, validity, error, and settings provenance. The previous valid value has separate provenance and age. Values from before a capture remain stale until refreshed, even if the restored configuration hash matches. A valid formatted S22 value comes from the firmware cache, so device freshness remains UNKNOWN. `?`, unverified formatted zero and invalid display strings have a null current value. This conservatively excludes genuine zeros until distinguished from the missing-cache representation.

## Capture and recovery scope

Triggered capture supports the ACQ-11 probe fixture with both channels enabled and DC-coupled, CH1 rising edge, Auto trigger, 200 µs/div, ordinary YT and Normal acquisition, 4K and MATH off. It snapshots configuration, applies only the verified vertical/probe edits, observes SINGLE reaching Stop, preserves the waveform, and restores and verifies the preceding configuration and acquisition mode. `native` reports unavailable stopped analog slots as a failed capture. `auto` attempts the native path first and falls back only after a settled unavailable result and compatible CSV state. `frozen` requires a visible CSV menu and established front media. Frozen capture uses the reviewed fixed read-only listing command and preserves only uniquely new, size-stable exports. It never removes front-media files. No same-shot or unattended reliability claim is made. [ACQ-11 protocol](NATIVE_WAVEFORM_ACQ11.md)

Known native conversion uses the verified viewport/timebase and S81 scale indices 7 or 9. Other combinations remain raw-only. Result estimates apply configured software probe attenuation and do not independently establish the physical probe switch or calibration. The waveform result identifies this configuration separately from S22 telemetry.

A FAULT state stops all USB commands. Inspect the private journal, raw exchanges and `service_fault.json`. Preserve any interruption marker or guard and reconcile the exact operation under the existing ADR-006 procedure before issuing another command. Normal restart uses a fresh evidence directory and the receive-only startup gate. There are no autonomous reconnect attempts, firmware changes or reset procedures.
