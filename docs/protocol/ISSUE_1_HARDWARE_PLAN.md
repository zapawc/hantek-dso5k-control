# HANTEK-DEV-01 — Proposed hardware qualification gates

**Review proposal. Each gate requires separate authorization and evidence from the preceding gates.** HANTEK-DEV-01 performed offline investigation only. For each approved session require operator-confirmed ownership, cooperative lease, settled history with no interruption marker, no concrete competing assignment, validated interface, and a quiet 12-second preflight. Preserve raw USB transfer boundaries, exact timestamps, frame decisions and partial artifacts. Keep one outstanding request, a 12-second full receive window from write completion, at least 550 ms inter-command quiet guard and zero automatic retries. S92 may be recorded only using the existing vetted policy where applicable, never as acquisition evidence. In a new candidate S02 window use strict traffic rules: unexpected status, unknown opcode, malformed framing, trailing bytes or transport error stop all further writes.

## B0 — Reuse the qualified read-only baseline

Use preserved S01/S20/S20/S01 first. Re-run this sequence only if contemporaneous configuration evidence is required by the next approved gate, with four writes maximum, exact validated bytes and existing transport budgets. Record panel observations if available. Expect a 208-byte settings payload at both ends and individually valid A0 frames. Report aggregate and strict-session discrepancies separately. Pass baseline stability on the documented stable-field comparison; unexplained stable-field drift, broken primary framing or ambiguous traffic blocks progression. Release the interface and lease on failure and leave the instrument settings as found.

## B1 — One CH1 display-buffer stream

This is the first new request proposed for approval. Before authorizing it, review the result of the callback/producer trace, approve volatile transfer-state effects explicitly and confirm existing CH1 display and acquisition are enabled through independent operator evidence or a separately qualified baseline. The stimulus may be an existing harmless input. Instrument state and electrical setup are held fixed. Complete replay tests before any opening. Use one exact CH1 request 53 04 00 02 01 00 5A. An optional contemporaneous B0 baseline is separate, and there are no fallback requests within B1.

Expect checksum-valid S82 count/data/terminal framing from the [matrix](ISSUE_1_EVIDENCE_MATRIX.md), or the defined single analog unavailable branch. For the first trial set a conservative host bound of 10,000 points, 16,384 received bytes and 256 frames. A larger legitimate path is out of scope and requires offline review. Capture the full window after a complete reply. Report streaming PASS only if the exact positive count is reconstructed, selector 0 is verified, a terminal is present, and no other traffic occurs. A clean unavailable reply records availability false while preserving framing. A known benign input can help judge plausibility; this gate leaves freshness, units and trigger timing unverified. On error or timeout, release cleanly, keep interrupted-history state if unsettled, and review the evidence. No second read, endpoint reset or queue clearing.

After B1 passes, separately authorize a CH2 counterpart using 53 04 00 02 01 01 5B once, with selector and display precondition set to CH2. Keep the same budgets, evidence, stop conditions and recovery rules. Confirm channel attribution using distinct known benign inputs if practical. This counterpart is independent of any frozen-buffer test.

## B2 — Front-panel readiness, one controlled shot and frozen readback

Requires B1 and a separately reviewed plan for reversible operator actions and CH2 availability/attribution. First observe panel state and read S01 before arm, once while independently witnessed ready and withholding the event, and once after one independently recorded internal trigger and panel completion. Fix Normal real-time acquisition, both channels visible, known coupling, edge, threshold, scale and timebase. Confirm settings interpretation and positive readiness from panel observations as well as S01. Stop the trial if readiness cannot be established within 30 seconds of manual arm or if the stimulus is absent 15 seconds after witnessed readiness. USB operations use their own fixed windows. Use at most three S01 and, after clean completion, one approved source-0 and one approved source-1 request (five writes maximum). Expect stable intended settings, a new event witnessed exactly once, and complete, source-attributable S82 pairs from the frozen state. An unavailable stream, an already-present event in the pre-arm evidence, or any contradictory state blocks qualification. Any timeout can leave the device armed; inhibit stimulus, settle transport, then have the operator assess the instrument and use the pre-approved manual procedure from a known state. Do not send a compensating toggle.

## B3 — Prove same-shot retrieval

Run only after B2 records both channels safely. Hold Normal real-time acquisition and a verified one-shot producer freeze/shared latch. Use a distinct non-periodic tagged event per trial, observed independently with its trigger edge and both analog paths. Bounded first series: one older reference, two new shots with different signatures, and one re-arm with stimulus withheld. Run the first new shot CH1 then CH2, the second CH2 then CH1 with one extra 2 s quiet delay, keeping prior time bounds and checking the delay for traffic. Use at most five USB writes per positive trial (three S01 plus one read per source), and at most four writes in the no-trigger trial (two S01 plus one read per source only if pre-completion reads have independently been cleared of unsafe effects). Perform manual restoration between trials as agreed; stop the series on the first failed or unclear gate. Use the same receiver bounds as B1 for each source.

A valid pair requires source attribution, both complete records, new matching event IDs/signatures, and trigger-relative alignment within a predeclared uncertainty budget derived from validated sample intervals, source skew and witness timing. Prespecify the numerical tolerance once those inputs are measured; the budget must distinguish a one-record substitution or a conflicting trigger, and overly coarse timebases fail the intended application. Also require direct evidence that both buffers share a generation, or a verified producer freeze/latch invariant covering both retrievals. The no-trigger trial must never accept an old pair as new even if bytes are returned. Use fixtures for dropped/corrupted/ambiguous sources, especially middle-source loss and duplicated stale pairs. The multisource selector remains deferred until direct source assignment and bounds are independently established. Periodic signal similarity alone cannot identify a unique event. Failure leaves any captured data available as unqualified observations.

## B4 — EXT input and remote keys are independent gates

**EXT input.** Perform a verification of the actual connector/mode and rated limits, applicable impedance, coupling, threshold, protection, grounds, and measured stimulus at the connector before approval. The vendor publishes distinct trigger-level ranges for EXT and EXT/5, which are threshold settings. Obtain the actual absolute input limit for this unit before connecting anything. Use a reviewed compatible bench stimulus and independent event witness. Consumer board rails or a power-switch event are outside this plan. Use manual configuration and B2's maximum five writes and deadlines, one withheld-event observation and one witnessed external event, followed by the separately approved manual restoration. Require readiness without the event, completion from the intended edge only, and a source/panel match. Apply B3 evidence if claiming same-shot EXT. Stop on rating, grounding, state, transport or source uncertainty and have the operator inhibit the source before bounded restoration. See [model specifications](https://www.hantek.com/products/detail/96) and the [series manual](https://www.hantek.com/Product/5000P/DSO5000P_Manual.pdf).

**Remote SINGLE.** Review UI key consumption, persistence, initial state and exact inverse first. Then replace the witnessed manual arm in a B2-style experiment with one separately approved candidate SINGLE key at most. Cap at six writes, including at most five B2 observations/retrievals. Expect S93 menu acknowledgment and independently witnessed actual readiness/completion. Unclear acknowledgment or incomplete readiness stops further USB writes; manual restoration only from a known state. RUN/STOP toggle, automated menu traversal, bulk settings apply and device-write recovery remain excluded.

For all trials preserve baseline settings and independent panel/run-state evidence before changes, then compare stable settings, source/mode and panel at the end. A mismatch is a restoration failure requiring operator review. Keep unresolved markers until a human verifies settled history. No reset, power cycle or automated retries are part of this proposal.
