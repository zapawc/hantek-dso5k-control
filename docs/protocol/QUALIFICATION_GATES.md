# Qualification gates

## First Windows read-only run, proposed for explicit approval

Use a reviewed immutable software version. Confirm active single-client ownership, settled history including any legacy commands, and no unfinished prior window. Check host PnP and redirector assignment under the existing cooperative lease. If the exact local target is found, verify bulk descriptors and claim once. Receive for 12 seconds before any transmission. Reject all startup traffic. Then run baseline settings, screenshot 1, screenshot 2, final settings. Capture each full response window and quiet guard. Preserve partial evidence and release the interface and lease. Stop on ambiguity. No automatic reconnection.

Require two framed settings replies and compare all configuration/unclassified fields, allowing the documented trigger-state byte and trigger-frequency counter to vary. Record individual screen frames, aggregate, display interpretation and qualitative plausibility independently. Mark strict status failed if async status or aggregate discrepancies are observed. No inference of trigger state from static images. Record the settled interruption state after evidence review.

## S02 waveform and buffer behavior

Review source selectors, callback side effects, buffer release and terminal paths on the original ARM application. The source-zero transfer-state branch is excluded. A later independent authorization can bound a single analog-channel observation, with a known signal and pre/post settings/screens, verifying sample count, channel, termination or explicit unavailable, and retention effects. Timing and volts need contemporaneous independent calibration. Any active panel lock or possible persistent effect is a separate gate.

## CH1/CH2 coherence

Prove a shared buffer generation or a common latch and identify the trigger origin statically before a paired trial. Test with a distinctive common event and verify index alignment independent of plausible periodic phase. Sequential reads or multisource ordering alone cannot prove a shared event.

## Trigger status and SINGLE

First establish an independent indicator that differentiates ordinary wait, armed SINGLE, new trigger, completion and operator stop. A host timeout communicates missing host evidence. Keep S22 availability and transfer status separate. Review the exact mode transition, time bounds and affected keys or fields. Run only after separate approval.

## Restoration

Require exact reversible operations, verified persistent side effects, complete before snapshot and independently verified runtime state. Compare documented stable fields and mode after the explicit inverse. Stop cleanly on partial or ambiguous mutation and preserve evidence. No bulk-settings fallback or blind RUN/STOP toggle.
