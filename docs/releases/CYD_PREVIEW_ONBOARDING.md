# CYD-RF-Diagnostic onboarding for the read-only preview

After an approved public release, choose the Hantek wheel by the reviewed deployment manifest and release digest. Copy the complete verified Windows lock into the consumer integration change. Record the full source commit, wheel SHA-256, CLI version 0.1.0 and capture schema version 2.0. Obtain upstream backend wheels separately and verify their digests. Install with the [consumer guide](../../HANTEK_INTEGRATION.md). Keep the lock, contract test, and recorded previous pin in CYD. Require an explicit consumer PR to change any pin.

Run `hantek --version`, verify the installed artifact provenance, and exercise offline settings conversion and fixture-based manifest acceptance. Treat exit 5 as a completed primary read-only batch with strict session FAIL. Never auto-retry this outcome. Verify hashes and per-step outcomes, and accept screen previews only if the CYD purpose is qualitative. When a separately authorized session is used, the Hantek CLI owns instrument transport and returns the documented JSON. The CYD project owns its own procedures, thresholds and reporting.

Document any need for trigger control or synchronized CH1/CH2 SINGLE in a shared Consumer integration request, linked to its downstream issue. This preview cannot drive automatic power-startup or verify trigger-relative timing.
