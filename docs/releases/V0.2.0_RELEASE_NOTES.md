# v0.2.0 release candidate — bounded native CSV retrieval

**Status: preparation only.** This document is proposed release text, not evidence that a `v0.2.0` tag, GitHub release, or distribution artifact has been published. Final wheel digest, source commit, checks, and publication authorization remain pending.

## Changes since v0.1.0

- Added `hantek offline file-replay` for integrity-checked replay and extraction of archived native S90 CSV response data. Offline operation does not open USB.
- Added `hantek files retrieve`, a tightly gated Windows command to retrieve one *already completed and exported* CH1 CSV from `/mnt/udisk/WaveData163.csv`.
- Added a versioned `file-transfer-v1` result schema, explicit file-byte and SHA-256 verification, evidence journaling, exact-frame S92 classification, single-client ownership checks and interruption-marker handling.
- Added protocol documentation, tests and a prior-art/reuse inventory linking existing implementation evidence to qualification limits.
- Preserved the `v0.1.0` read-only settings/screenshot qualification flow and existing capture/settings schema 2.0.

## Hardware qualification and limits

On 2026-11-20 UTC, an installed DEV-07 CLI built from reviewed source commit `895c518eeb3cac8333bc5960fc2d3fdff0b6992d` retrieved the prior completed CH1 file from an original-firmware DSO5102P under separately authorized supervision:

- Exactly one S10 request, zero retries; complete 12-second receive-only preflight with zero bytes.
- Nine S90 data frames and one terminal frame, terminal sum `C3`; zero S92 observed in this packaged CLI run (S92 was observed with the DEV-06A predecessor).
- Exactly 89,566 bytes retrieved, independently matching SHA-256 `69080b701123c1a5faeac60eb571205c43f4e96517f9f8485451739296ea31f4`.
- Verified local output publication, interface and cooperative lease release, interruption marker cleared; operator visually confirmed both traces remained frozen and RUN/STOP red.

The manifest reported `source_commit: null`; the reviewed source revision was verified independently during staging. This qualifying command applies only to the above CH1 filename, fixed-size profile and observed conditions; it is not a general file browser or waveform-streaming interface. Packaged S92 handling, fragmentation and failure paths have offline test coverage beyond this particular live run.

**Not qualified:** CH2 S10 retrieval, multiple sequential retrievals, arbitrary filenames/sizes, remote CSV Save/Recall, remote SINGLE or EXT triggering, fresh acquisition, sample freshness, simultaneous CH1/CH2 sample identity, live S02 retrieval, clock writes/synchronization, configuration changes, and firmware modification.

The older read-only batch's qualitative screenshots retain their documented graphics aggregate discrepancies and strict session FAIL/exit 5 outcome; these are not silently recast as strict success.

## Installation and provenance

The source package requires Python 3.10+. Windows hardware use needs separately approved access and the pinned optional WinUSB dependencies. Building and installing must not open USB. Consumers should pin the *approved release artifact SHA-256* or full reviewed commit and test their own compatibility before upgrading. Do not treat the package version alone as complete provenance.

**Release checklist still required:** offline Python/PowerShell CI against the final release candidate; reproducible wheel/sdist build and artifact hashes using the [offline build procedure](V0.2.0_BUILD.md); license, privacy, dependency and distribution audit; final tag policy/source-commit verification; explicit release publication authorization. No additional Hantek hardware test is required merely to repeat DEV-07's already qualified CH1 operation.
