# v0.2.0 offline build and verification

Use two clean exports of the approved full Git commit and fresh, isolated build environments. Follow the [preview build input and isolation procedure](V0.1.0_BUILD.md) with the same [hash-locked tools](v0.1.0-build.lock). The tested recipe uses Windows x64, CPython 3.11.7, bootstrap pip 23.2.1, setuptools 70.0.0 and wheel 0.43.0. Install tools with `--no-index --require-hashes` from the approved wheelhouse. Set `SOURCE_DATE_EPOCH` to the full commit's Unix committer time (`git show -s --format=%ct <commit>`) and set `PYTHONHASHSEED=0`. Record these values, full source SHA, OS, Python/zlib versions and tool digests with the output hashes. Use separate empty output directories for each build.

From each clean source export, run the backend and normalize the resulting sdist. Paths below are examples for native Windows PowerShell. Create the two absent directories before the build and leave the final output file absent.

```powershell
& $BuildPython -c "from setuptools import build_meta; print(build_meta.build_sdist('dist-raw'))"
if ($LASTEXITCODE) { throw 'sdist build failed' }
& $BuildPython tools/normalize_sdist.py dist-raw/hantek_dso5k_control-0.2.0.tar.gz dist-final/hantek_dso5k_control-0.2.0.tar.gz
if ($LASTEXITCODE) { throw 'sdist normalization failed' }
```

Use the normalized archive for release review. The normalizer preserves each regular file's bytes and the directory names. It accepts ordinary files and directories under one archive root and rejects unsafe, duplicated, or unsupported members. It writes entries in name order using fresh PAX tar headers, with mtime from the epoch, file mode 0644, directory mode 0755, numeric ownership zero, and no owner names. It sets the gzip header's timestamp to the same epoch and omits the original filename. It preserves the untouched backend output as evidence. Stock setuptools output is not claimed reproducible. Require equal sizes and SHA-256 for both normalized sdists using the recorded toolchain.

Inspect the normalized archive and run all 39 synthetic tests directly from a clean extraction with `src` on `PYTHONPATH`. The archive includes all three versioned schemas and the bundled unit tests. Build a wheel from a clean Git export and another from the extracted sdist, require equal hashes under the same environment, and install the wheel in a separate fresh environment. Confirm version, entry point, retrieval flags, schema contracts, license and notices. Verify the [optional backend wheel hashes](v0.1.0-win-amd64-backend.lock) separately. No tool in this procedure requires device access.

The installed manifest may have `source_commit: null`. Use the approved full source SHA plus wheel SHA-256 as the external provenance pair. Record the normalized sdist digest separately. Generate those digests from the final approved commit and record them in the release evidence. Neither a local build nor successful CI authorizes publication.
