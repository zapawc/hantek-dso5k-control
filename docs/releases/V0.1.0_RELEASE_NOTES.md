# v0.1.0 read-only preview

Qualified on the original Hantek DSO5102P with Windows 11 x64, CPython 3.11.7 x64 and WinUSB using the documented gated four-request batch. The tested unit's historical firmware baseline is 3.40.0 (151009.0). The sanitized candidate uses capture and settings schema 2.0. The new output schema was validated offline against the qualified local precursor.

- Windows USB discovery and cooperative ownership checks as part of `hantek qualify readonly`.
- Read-only baseline and final settings with stable field comparison.
- Two qualitative 800 × 480 RGB565 screen previews.
- Structured manifest, raw transfer evidence, frame checks and independent graphics integrity results.
- Offline decoding of saved settings and offline conversion of a bounded historical CH1 waveform using caller-supplied scale and timing.

All four primary replies in the historical qualification passed. The 199 stable settings bytes matched. Each screen was readable and had a graphics aggregate checksum discrepancy. Each also had one exact classified post-primary S 0x92 status with unresolved origin. **Strict session integrity was FAIL. The CLI returned exit 5 as designed.** Consumers should inspect each primary result and preserve the strict failure. Previews are suitable for qualitative observation. Atomic screen coherence, acquisition freshness and trigger completion remain unverified.

Trigger changes, SINGLE, live waveform retrieval/coherence, power-startup automation, settings restoration, RTC synchronization and firmware modification remain unqualified or unavailable. Installation and CI never open the scope. An actual read-only session requires separately approved access, confirmed single-client ownership and settled history. Consumers verify and pin the exact release wheel SHA-256 or approved full commit. [Capability matrix](../capabilities/CURRENT.md) · [CLI contract](../CLI_CONTRACT.md)
