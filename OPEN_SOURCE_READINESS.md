# Open-source readiness

**The repository and v0.1.0 preview are already public. The proposed v0.2.0 release remains unpublished and requires separate, exact-artifact approval.** The operator selected MIT and retained the normalized settings schema. Historical publication controls below describe the original launch; they do not override the present repository state. Private qualification captures and proprietary instrument evidence remain off-repository.

The existing hardware qualification supports Windows discovery through the guarded path, read-only settings, qualitative screenshots, structured evidence, and caller-parameterized offline conversion. Successful primary responses and strict FAIL/exit 5 remain separate. Trigger and SINGLE control, live waveform coherence, power-startup automation, restoration and clock changes remain unqualified.

## Approval gates

1. Review the final manifest, approved MIT text, sanitized history and release asset digests. Keep the canonical local ancestry and private evidence outside the public repository.
2. Review public Issues and PR moderation, offline CI and release scope. Grant new release-publication authorization separately for the exact destination, commit, tag and assets.

## Public issue safety

Public GitHub issues, comments and attachments can expose material immediately. The five issue forms and contribution policy exclude sensitive material, but text filters and GitHub scanning cannot guarantee prevention. Use reviewed synthetic/minimized reproductions and opaque project IDs. Keep raw captures, complete manifests, credentials, private links and proprietary evidence local. Withhold an issue requiring restricted evidence. If exposure occurs, notify the maintainer, revoke affected credentials and coordinate removal. Copies may persist.
